# Category data quality — TR-002 (2026-08-27)

Fixes the three degenerate categories of the task-router percentile scale:
`guard`, `mock` (saturated), and `multilingual` (neutral). Root-caused a
pre-existing tier-computation bug that made the ±5 scale a no-op in EVERY
category. All changes are regenerated by `scripts/router_seed.py` (never
hand-edited JSONL).

## 1. The three degenerate categories (before)

| category | before | why |
|---|---|---|
| guard | 40/59 models at 1.0, 9 at 0.0, 10 surveyed mid values → 2 tiers (−2, 5) | perf sourced from `battery-T4-INSTR-floor` — a pass/fail instruction-following FLOOR test, all 1.0. Not a graded capability measure. |
| mock | 41/59 at 1.0, 8 at 0.0 → 2 tiers (−2, 5) | same T4 floor source. |
| multilingual | 59/59 at neutral 0.50 → 1 tier (5) — every model "max multilingual" | no benchmark/survey signal; the seed's neutral fill for new categories. |

## 2. Root cause found: cross-category tier leakage

`model_tier` joined `category_levels` with only `cl.min_perf <= mp.perf` — NO
`cl.category = mp.category` condition. Every model's tier was the max level
across ALL 24 categories' thresholds, so a low-spread category's level-5
threshold (e.g. old review q99 ≈ 0.8) granted tier 5 to any model with perf ≥
0.8 in ANY category. Proof from the pre-TR-002 backup
(`routing.duckdb.pre-t002`): `deepseek-v4-flash` reasoning perf 0.7 → tier 5,
while reasoning's own level-5 threshold is 0.9826 (correct tier = 0). The
de-saturation of guard/mock was the visible symptom; the leak was silently
inflating every category's tiers and making all seeded profile levels
meaningless.

**Fix:** `JOIN category_levels cl ON cl.category = mp.category AND cl.min_perf <= mp.perf`.

Consequence: honest tiers are systematically lower than the inflated ones. The
seeded profiles' requirement levels (written against the inflated scale) were
re-based so each profile keeps its exact pre-TR-002 chain membership (heads,
ordering semantics, scheduler behavior unchanged — TR-002 AC3). Re-based
levels are the tightest honest level that admits the profile's pre-fix
members per category; see `router_seed.py` `PROFILES`.

## 3. Data sources / decisions (per category)

Policy: surveyed mid-range values (0.6–0.9, entered from vendor signals) are
PRESERVED verbatim; only degenerate values (guard/mock ∈ {0, 1}; multilingual
= 0.50) are replaced, by model-NAME keyed family priors applied to every
provider row of that model. 157 rows replaced, idempotent per run.

- **guard** — agentic reliability / anti-hallucination grounding (per the
  `anti-hallucination-grounding` → guard tag mapping). T4 floor is pass/fail
  and stays in `benchmarks` as provenance; graded estimates calibrated to the
  surveyed anchors (glm-5.3 0.80, gpt-oss-120b 0.80, qwen3.8 0.72–0.75,
  qwen3.6-27b 0.70): agentic workhorse families (deepseek-v4, kimi-k3/k2.7,
  minimax-m3, step, glm-5.2, mimo-v2.5) 0.85–0.90, western flagships
  (gpt-5.6, gpt-oss-120b, mistral, nemotron-3-ultra) 0.78–0.92, edge/small
  models 0.60–0.72. **Estimate — flagged, no registry benchmark graded guard.**
- **mock** — data-fabrication realism. Surveyed anchors respected (qwen3.8
  family high 0.75–0.90, glm-5.3 family low 0.60); floor group graded
  0.68–0.88 by family. **Estimate — flagged.**
- **multilingual** — **data-free decision (flagged):** no registry benchmark
  measures multilingual capability (checked: benchmarks table, model-intel
  verified-data refs 08-24..08-27). Estimates are family training-data priors:
  Chinese-first families (deepseek/qwen/glm/kimi/step/minimax/mimo) 0.86–0.92,
  western flagships (gpt-5.6, gpt-oss-120b, mistral, nemotron) 0.78–0.82,
  edge/small 0.62–0.72. Replace with real MMMLU/MGSM-style data when a source
  is wired.

Alias handling: offpeak/fast/cloud variants inherit their surveyed sibling's
value (glm-5.3-offpeak == glm-5.3; glm-5.3-flash-offpeak == glm-5.3-flash;
gpt-oss:20b == gpt-oss-20b; gemma-4:31b == gemma-4-31b; k3 == Kimi K3;
deepseek-v4-flash:0731 == deepseek-v4-flash; kimi-k2.7-code-fast ≈
kimi-k2.7-code).

## 2026-09-01 — the deepseek review-0.60 incident (stale estimate → silent head loss)

What happened: ollama-cloud/deepseek-v4-flash:0731 ($0.033) vanished from every
P0_FORE chain. Cause chain: (1) `perf_review: 0.6` was born in the TR-010
migration (08-27 10:00) as a NEUTRAL-family fill and never corrected — the
documented 08-27 fleet-evidence correction (code-review '+') lives in
PROFILE_TAGS, but that function only fills NEW categories, so for OLD columns
(review/reasoning/long_doc) it is dead code; (2) the 08-29..08-31 evidence
slices added strong-review families (glm-5.2 0.88, kimi-k3 0.85), which pushed
the review q10 boundary 0.60→0.61; (3) 0.60 < 0.61 → review tier -2 < required
-1 → filtered in _build_chain BEFORE the gate stage → invisible (no exclusion
row, no gate_reason). glm-5.2 ($0.05 unsourced ollama-cloud estimate) took the
head by default.

Fixes shipped:
- data: deepseek-v4-flash review 0.60→0.72, reasoning 0.70→0.85,
  long_doc 0.55→0.72 on all 7 live lanes (the documented 08-27 values).
- seed overlay (apply_overlay): measured benchmark scores now beat ANY lower
  estimate, not just the 0.50 neutral — estimates lose to evidence.
- spawn ROUTER-MISS: every profile-requirement filter now prints
  `ROUTER-MISS: <provider>/<model> fails <cat>>=<lvl> (tier=N)` to stderr —
  a head-losing filter is visible in minutes, never silent again.

Lessons for the daily data-quality agent:
1. Corrections to OLD-category perfs must land in data/tables/models.jsonl
   rows directly — PROFILE_TAGS cannot carry them.
2. Unsourced price estimates (price_evidence: "estimate") should be probed —
   the $0.05 glm-5.2 estimate outranked sticker-priced lanes for a day.
3. After every evidence slice, diff the HEAD of the big profiles
   (P0_FORE/P8_SYNC): `router_spawn.py <p> --format json | jq .head`.
