## Worker trap (hit + recovered this tick)

`ROUTING_DATA_DIR` does NOT redirect `registry.json`. Running the seed from a
control worktree with `ROUTING_DATA_DIR=<worktree>/data/tables` but no
`ROUTING_REGISTRY` override silently DUMPED the stale (1838-row) registry into
the main repo's gitignored `registry.json` — the live spawn surface then read
old data until the next real seed. The TR-048 NS guard covers `ROUTING_NS`
overrides only. Rule for control runs: set BOTH `ROUTING_NS` and
`ROUTING_REGISTRY` to scratch paths (or verify `rs.REGISTRY` after import).
Recovery here: real seed re-run against committed data/tables (byte-identical
derived tables — idempotence re-proven); spawn read-back shows live 1494 /
retired 347 (= −19 retired, +3 new rows vs pre-change 1510/328).
