1 · What "proxy" means here

A caller (the scheduler's foreman, or anything else) wants Hermes. It does not pick the model — it calls task-router, which stands in as the proxy and does the selection:
  1. reads the incoming prompt,
  2. has the model rate its complexity by category (per-prompt, never a fixed profile),
  3. looks the chain options up in the task database for those requirements,
  4. calls Hermes in chain order, walking the fallback chain when a hop fails or is gated,
  5. lets the turn run (minutes-long agent sessions, bounded by idle time, not a wall clock),
  6. returns the answer plus the stats — and writes the same facts to the ledger, so the data exists for cost-per-task, seat audits and "which model is actually good at this category".
Everything below tests that chain of custody end to end.
