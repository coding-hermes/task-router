# Test-coverage baseline & floor — 2026-09-30 (TR-187)

First measured test-coverage baseline for the runtime modules in `scripts/`
(TR-187). TR-064's `docs/coverage-2026-09-19.md` is a different artifact: it
measures registry *complexity* coverage (tier evidence per lane), not code
coverage. This file establishes the code-coverage baseline, the floor that
fails the suite when coverage drops below it, and the concrete gaps.

## The floor

```
FLOOR = 49.5%   (baseline 50.53% minus a 1.0pt margin, rounded to the half-point)
```

The floor rides the same command that measures (CI installs only
pytest+duckdb+pyyaml, so `--cov-fail-under` is deliberately NOT wired into
pytest addopts — that would break every plain `pytest -q tests/` run):

```bash
~/.hermes/venvs/board/bin/python3 -m pytest -q tests/ \
  --cov=scripts --cov-report=term-missing \
  --cov-report=json:data/coverage-baseline.json \
  --cov-fail-under=49.5
```

Exit code 1 when the measured total drops below the floor (measured with
pytest-cov 7.1.0: `--cov-fail-under=99` over a green subset exits 1 while
all its tests pass) — the run refuses to pass the suite. Re-baselining: re-measure, update
`data/coverage-baseline.json`, set the floor in `data/coverage-floor.json`
to the new baseline minus the margin, and land both together with the doc
numbers refreshed. Never lower the floor without re-measuring first.

## The 22 modules at 0% — three classes

`scripts/test_fleet_cooldown_policy*.py` are themselves in the measured set
(standalone scripts, imported by no test — by design).

   `board-merge-driver.py` (tests/test_board_merge_driver.py) and

## Five largest gaps — the specific untested behaviour

### 1. scripts/fleet-cooldown-policy.py — 333 missing lines

- `verify_pins()` correction rules: live cooldown below the 3600s fast tier
  is treated as wake residue and REVERTED to the fleet.toml pin (or the fast
  tier when no pin exists); 3600-with-matching-pin stays untouched; above
  21600 with real work reduces to 21600; below 21600 with a foreign pin
  raises to 21600; promotions to 43200 only on empty boards.
- The cooldown_floor_s re-snapshot that must ride EVERY policy PUT (a stale
  sub-6h floor re-poisons the pin on the next committing tick — the
  measured h3 900s-vs-43200pin incident).
- `verify_deploy_hash()` / `write_canonical_hash()`: sha256 deploy-hash
  verify/write used by the scheduler pin checks (only reached by the
  standalone scripts, untraced).
- `read_fleet_pins()` / `write_fleet_pins()` fleet.toml round-trip —
  [[namespaces]] blocks must survive regeneration (the out-of-tree script
  tests exactly this, so in-tree coverage stays 0%).

### 2. scripts/board-merge-driver.py — 254 missing lines

Subprocess-tested (class 1), so these behaviours ARE pinned in
tests/test_board_merge_driver.py but invisible to the tracer: the
order-independence invariant (swapped sides produce byte-identical output),
idempotent re-merge, stable ids, same-id-different-content collisions
keeping BOTH rows, newer-timestamp field-merge, and the failure-refuses-
to-write contract. Coverage data must not be read as "untested" here — the
blind spot is the tooling, not the suite.

### 3. scripts/proxy_acceptance.py — 248 missing lines

Live-only by design; the unmeasured logic is the acceptance gates themselves:
`gate_scheduler_shape()` (chat-completions shape, no keepalive assumption),
`gate_session_keying()` (caller session-key derivation), `gate_failure_
honesty()` (envelope vs status agreement), `gate_custody()` (ledger +
state.db cross-check), `gate_stats_live()` (counter-increase assertion),
`gate_write_safety()`, plus the SKIP-with-reason rule for unmeasurable
checks and `--json` evidence emission. Any in-process test of these would
violate the battery's own live-only contract (TR-186).

### 4. scripts/router_rank_audit.py — 227 missing lines

- `family_pairs()` version ordering: (provider, family, version) grouping
  that decides which sibling is "newer".
- Section 2 INVERSIONS: newer generation carrying fewer tier rows than an
  older ACTIVE sibling — the fleet routes the old model.
- Section 3 BIRTHDAYS: ranked rows with no release_date (generations
  cannot be ordered).
- Section 4 DECAY: superseded-but-fully-ranked rows, split into
  safe-to-retire vs rank-first-then-retire.
- Fail-open exit 0 (always) — an audit that crashes must never block a tick.

### 5. scripts/router_ledger.py — 162 missing lines

Subprocess-tested (class 1, tests/test_ledger.py pins the CLI contract);
unmeasured despite real coverage: `cmd_status()` in-flight accounting
(last-row-started per (provider, model), started rows older than 30 minutes
excluded as stale) and last-outcome reporting; `cmd_end()` fail-open
behaviour (unknown trace_id → stderr warning + still appends + exit 0) and
the invalid-outcome exit 2; `_read_rows()` torn-line handling with the
per-line TR-244 warning; verbatim (data-not-flags) handling of
--project/--profile/--requested-pair/--reason values.

### Near-misses (worth the next gaps, not in the top five)

- `scripts/router_tier_coverage.py` (155 missing, 0%): `measure()`
  conjunction semantics — satisfiable-vs-registry vs satisfiable-vs-eligible,
  the per-category blocker attribution (`cat_fail` = thinnest-support
  category), and `clears()` alias-aware level comparison.
- `scripts/board_stall_check.py` (179 missing, 0%): `classify_row()` stall
  semantics (non-terminal lifecycle AND worker_status in
  dispatched/in_progress), `worktree_state()` liveness (absent path = dead;
  present path live only if `git status` succeeds; OSError =
  `worktree_check_error`, row stays flagged), and `--requeue` id-targeted
  event append + single-row rewrite.
