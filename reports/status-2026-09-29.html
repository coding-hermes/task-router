4 · Admission: the reason the flip is blocked

measured, and it agrees with Bane's instinct
ROUTER_PROXY_MAX_INFLIGHT   default 8    concurrently executing requests
ROUTER_PROXY_QUEUE_MAX      default 32   requests allowed to WAIT
ROUTER_PROXY_QUEUE_WAIT_S   default 20   then refusal

ceiling = 8 + 32 = 40 in flight      vs     366 ENABLED LANES
refusals in the 168h window: 60 rows with failure_reason='overloaded' (2 in the last 24h)

The design answers "how do I protect myself from load" when the load is our own scheduler. A refusal is silent work-loss for the fleet. Two more things make it worse than it looks: a task can consume up to max_hops=3 upstream attempts, and a refused row carries no caller identity (provider=none, model=none), so a rejection of our own work is indistinguishable from defence against a stranger.

The gate I built to make this impossible to ignore let every push through. scripts/ci_gate_check.py asks for runs on the sha being pushed; a brand-new commit has none, so it prints has no completed run — proceeding — which is exactly what it printed on all four of tonight's pushes, one of which then went red. The intended law was "refuse while main is red", so the check must also read the remote branch tip's newest completed run. Filed as TR-240 with a two-arm test (main tip red → refuse; green → proceed).

6 · Complexity: agreed, mostly built, one field in the way

prompt -> scorer (x-router-scorer header or ROUTER_SCORER env; llm classifier | jev) -> matrix -> chain
  • Already true: the scorer is selectable; JEV is wired end-to-end; prompt classification is the default path (56 of 84 scored rows); every row carries the scorer's audit trail; failures are never frozen.
  • The one thing in the way: a caller that declares a profile gets source: 'declared' with matrix: None — the prompt is never read. That is why lanes behave like preset buckets.
  • Three defects: the scorer answered in prose on a real 7,652-character Hermes prompt (parse: no-json → floor profile); JEV has only 3 band rows; classification cost and latency are attributed nowhere.

Full detail in the companion artifact: reports/complexity-dynamic-design-2026-09-29.html.
