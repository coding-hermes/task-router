Timeout & failure-class alignment

Built from the failure-path report (TR-136/TR-137). The goal: the router must always answer before the caller gives up, so callers receive an explainable envelope instead of their own blind timeout — and every failure class means exactly one thing.

✘ buffered hop killed at 180s while the caller waits 1800s ⚠ one file, two different budget rules ✔ refusals already carry 429 + Retry-After

one other path: timeout = max(_proxy_hop_timeout_s(), _hermes_idle_timeout_s())   <-- a second, different rule

The misalignment: a buffered hop is killed 10× earlier than the client's patience. A model that is slow but alive gets reported as a hop failure at 180s while the caller was still willing to wait 1800s — and the natural reaction to a hop failure is a retry, which multiplies load. That is the mechanism behind "systems freak out".

2 · The invariant to enforce

inner budgets must expire BEFORE the outer one, with margin
hop_budget   < caller_tolerance  - margin        (proposed: 1500 < 1800 - 300)
idle_budget  < caller_tolerance  - margin        (so the router answers first)
envelope     always delivered by the router, never by the caller's own timeout

Today's acceptance check is too weak to catch this: budget_alignment passes when idle >= tolerate/2 — i.e. the proxy may give up at half the caller's patience and still be graded aligned. It should require the ordered relationship plus a margin.

Two precedents this table exists to stop repeating: TR-096 (a client-fault rejection burned the whole ladder because it was treated as retryable) and TR-136/137 (a failure envelope with served_by, usage, cost, session all null, and a slow-but-alive hop reported exactly like a dead one).

4 · The changes to make

#ChangeWhy
1One budget rule: the buffered-hop budget raised (180 → 1500) and the two code paths that compute a hop budget unified.A slow-but-alive hop is never killed 10× before the caller gives up.
2The invariant asserted in tests: hop_budget < tolerance - margin and idle_budget < tolerance - margin.Ordering is a property to check, not a hope.
3budget_alignment tightened from idle >= tolerance/2 to the ordered relationship.The gate must not grade a half-budget as aligned.
4The live ladder exposed in the health payload / /proxy/stats.An operator sees the budgets instead of grepping defaults.
5The class → caller-action table implemented as one constant the tests import, and enforced per class.No class unmapped; no client inventing its own interpretation.
6Any provider-pointed client states its patience; a client below the router's idle budget is detectable.The smallest number in the chain must not be the client's.
