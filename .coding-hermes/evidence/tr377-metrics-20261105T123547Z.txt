## Label rule compliance (row AC) — and the one provable gap, stated

- `router_resolve_total{profile,outcome}` — carries both, PLUS the served
  top hop's `provider`/`model` (empty strings when nothing was served).
- `router_chain_hops` — `{profile, outcome}` chain-length series for every
  resolve, PLUS a `{provider, model}` sample set per chain lane observing
  the lane's 1-based hop index (the "provider/model sample set where a hop
  datum exists" the row asks for; a family's samples may legally carry
  different SUBSETS of its declared label set — one registry, one writer).
- `router_lane_excluded_total{reason}` — carries `reason` from the
  resolver's OWN machine-readable vocabulary (the payload's `codes`,
  derived from `EXCLUSION_REASON_CODES` — no parallel vocabulary invented),
  plus the excluded lane's `provider`/`model`. One increment per resolver
  exclusion code: a lane dropped for N why-reasons increments N times (its
  HELP text says so).
- `router_lane_coverage{category}` — the ratio is a per-category population
  measurement (measured-with-evidence lanes / live lanes). It carries
  provider/model only in its DECLARED label set (kind="lane" marker series
  name the measured lanes; ratio/unmeasured series leave them empty) —
  a per-lane ratio row does not exist as data, and one series per live
  registry lane (~1205) is exactly the cardinality explosion spec §7
  forbids. Stated here per the row's "a stated reason, never a silent gap".
- `router_resolve_duration_seconds` — `{profile, outcome}` series per
  resolve plus a `{provider, model}` series keyed by the served top lane.

## Exposure decision: loopback-scoped (peer-level), bind unchanged

The servers bind 127.0.0.1 by default and this row does NOT widen any bind
(that is owner-gated TR-378). The route additionally checks the TCP PEER
address (`_peer_is_loopback`, `ipaddress.ip_address(...).is_loopback`,
IPv4-mapped forms accepted) and answers 403 to any non-loopback peer,
failing CLOSED on an unparseable peer. The document leaks provider mix and
cost, so a bind-address-only gate was judged insufficient for the row's
"loopback-scoped or token-gated" requirement; the peer check holds even if a
later row widens the bind. Chosen over token-gating because the API's
existing key path (`ROUTER_EDIT_API_KEY`) gates MUTATIONS, not reads —
retrofitting a key onto a read route would have broken every existing read
client's contract; the loopback scope matches how :9092/:9391 are actually
deployed.
